- Added unattended operation to `setup_system.py` via `--unattended`, `--sudo-password-file PATH` and `$JL_SUDO_PASSWORD`. **There is deliberately no `--sudo-password=` flag**: command-line arguments are visible to every user on the box through `ps` and land in shell history. The password is never put on a command line internally either — it is written to a mode-0600 file inside a mode-0700 private temp directory and exposed to sudo through `SUDO_ASKPASS`, with both overwritten and removed via `atexit`. Keeping the secret in its own file rather than embedding it in the helper script means no quoting or delimiter in the password can break the helper. The password is validated up front with `sudo -A true` so a wrong one fails immediately instead of 40 minutes into an OpenCV build.
- `SUDO_ASKPASS` is the right mechanism here specifically because sudo cannot prompt without a terminal — this session already hit that: `sudo -v` followed by a script that calls `sudo` internally failed with "a terminal is required to read the password", because the timestamp does not carry across processes without a tty. `run()` rewrites bare `sudo ` to `sudo -A ` when a password is armed; steps that hand a whole script to sudo (`sudo bash base_tools.sh`) need nothing, since the nested sudo calls inside those scripts already run as root.
- `--unattended` also defers steps marked `interactive` (the jetson-io TUI, `gh auth login`) rather than blocking on `input()` forever, and prints the exact `--only` commands to finish them afterwards.
- Verified all of it on this machine: wrong password rejected immediately; correct password ran `sudo -A bash install_services.sh` to completion with no tty and no prompt; the askpass temp directory is cleaned up afterwards (no `/tmp/jl-setup-*` left); interactive steps defer instead of hanging (run completes rather than timing out); and a world-readable password file produces a mode warning.
